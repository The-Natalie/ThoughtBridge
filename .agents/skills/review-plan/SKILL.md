Argument handling:
- Treat `$ARGUMENTS` in the referenced command as a placeholder for the `<plan-path> [--build-list <path>]` supplied with this skill invocation.
- Substitute the user's actual paths wherever `$ARGUMENTS` appears.
- Never treat the literal string `$ARGUMENTS` as a file path.
- If the plan path is missing, follow the command's resolution rules; ask the user when it cannot be resolved.
- If a supplied file does not exist, stop and report the missing file.

Preserve the original command's resolution rules, review procedure, correction loop, constraints, failure handling, and terminal-output restriction.

The review step is pure: do not modify the plan to produce the review; when the workflow stages the review outside the canonical directory, place the generated bytes verbatim at the canonical path with the file-editing tool. The correction step revises only the plan file and appends only to its `## Revision History`. Do not write code, fix implementation issues, or run tests. Do not automatically invoke `/execute` or `/commit`.

After stopping, insert the stage summary into the canonical review file as its leading `## Stage Summary` section immediately below the `Overall:` line with the file-editing tool, then follow the original command's terminal-output restriction: print only that same summary plus the plan and review paths.
