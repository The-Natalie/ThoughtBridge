Read `.claude/commands/review-execution.md` and follow its instructions in order.

Argument handling:
- Treat `$ARGUMENTS` in the referenced command as a placeholder for the `<plan-path> <execution-report-path>` supplied with this skill invocation.
- Substitute the user's actual paths wherever `$ARGUMENTS` appears.
- Never treat the literal string `$ARGUMENTS` as a file path.
- If paths are missing, follow the command's resolution rules; ask the user when they cannot be resolved.
- If a supplied file does not exist, stop and report the missing file.

Preserve the original command's resolution rules, review procedure, correction loop, constraints, failure handling, and terminal-output restriction.

The review step is pure: do not rerun tests, start servers, install dependencies, modify code, fix issues, or edit the plan or the execution report to produce the review. When the workflow stages the review outside the canonical directory, place the generated bytes verbatim at the canonical path with the file-editing tool; never alter review content. The correction step appends only `## Follow-up Validation (cycle N)` sections to the execution report and makes only routine fixes confined to the plan's scope, each with re-validation evidence. Do not automatically invoke `/commit`.

After stopping, insert the stage summary into the canonical review file as its leading `## Stage Summary` section immediately below the `Overall:` line with the file-editing tool, then follow the original command's terminal-output restriction: print only that same summary plus the execution report and review paths.
